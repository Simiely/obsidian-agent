# 10 - 代码梳理与重构计划

> 本文档是 M0-M5 完成后的**全量代码梳理**：现状模块地图、静态检查硬证据、最佳实践差距、重构计划（R0-R6）。
> 目标：消除重复逻辑与类型隐患，让代码库长期可维护。

---

## 1. 现状梳理（2026-07-31 完成时快照）

### 1.1 代码规模

| 范围 | 行数 | 说明 |
|---|---|---|
| `app/` 后端 | ~2100 | core 领域 + agent + api + config + main |
| `tests/` | ~1400 | 98 用例全绿 |
| `scripts/` | ~400 | 冒烟/上传脚本 |
| `frontend/` | ~1100 (Vue) | 5 组件 + md.js + styles |

### 1.2 模块地图与依赖方向

```
app/main.py  create_app 工厂（组装服务 + 挂路由 + 异常映射 + lifespan）
   │
   ├── app/api/*         路由层（薄 HTTP 适配，依赖注入 AppServices）
   │     deps.py         AppServices / require_auth / ensure_writable
   │     routes_*.py     vault · search · index · backup · agent
   │
   ├── app/agent/*       AI 层（Pydantic AI）
   │     llm.py 模型配置 · safety.py 写前安全 · service.py AgentService+PendingStore
   │
   ├── app/core/*        领域层（不依赖 Web 框架）
   │     vault.py   Vault 文件门面 + VaultWatcher（~300 行）
   │     backup.py  BackupEngine/Runner/Scheduler/Cron/Retention（~400 行）
   │     markdown.py frontmatter/标题/wikilink 解析
   │     indexer/   base(协议) + fts5(实现) + service(编排)
   │     search.py  SearchService（检索结果包装）
   │
   └── app/config.py     全部配置（pydantic-settings）

frontend/src/*   Vue3：App + FileTree/DocView/SearchPanel/ChatPanel + md.js
```

**依赖单向性已验证**：`api → agent/core → (config)`，core 不 import Web 框架 ✅（这是最大的架构资产，重构时保持）。

### 1.3 静态检查硬证据（重构依据）

| 工具 | 问题数 | 主要类别 |
|---|---|---|
| ruff | **81** | E501 行过长 23 · **B008 函数默认参数调函数 20**（FastAPI `Depends()` 标准模式，需配置忽略）· UP012 19 · F401 未用 import 6 · 其余 13 |
| mypy | **78** | **`dict` 缺类型参数 60+**（routes 层应改 `dict[str, Any]`）· sse_gen/内部函数缺返回注解 · 少数未标注 |

> **结论：逻辑健康（98 测试全绿），工程卫生欠账**——81+78 项全是风格/类型问题，无逻辑错误，但会拖慢后续维护。

## 2. 最佳实践参照（2026 分层架构标准）

调研结论（fastapi 官方 / pythonz2h / 企业级脚手架指南 2026）：

| 最佳实践 | 本项目现状 | 差距 |
|---|---|---|
| 分层 Routes → Services → Repositories | ✅ api 薄路由 + core 服务层 | core 内 vault/index/backup 兼具 services+repositories 角色，命名已可读，**不强行拆分** |
| 路由只做 HTTP 适配 | ✅ 已做到 | - |
| **Schemas/DTO 层**（请求/响应类型化） | ⚠️ 请求模型内联在 routes，**响应用裸 dict** | **R1：建 `api/schemas.py`，响应类型化**（同时解决 mypy 60+ 项） |
| 集中配置（Pydantic Settings v2） | ✅ config.py | - |
| 依赖注入 | ✅ Depends + AppServices | - |
| 自定义异常集中定义 | ⚠️ 异常散在 core（VaultError/BackupError/SafetyError），映射在 main | **R3：集中到 `core/exceptions.py` 或维持现状并文档化** |
| 工具链（lint/type 全绿） | ❌ 未跑通 | **R0** |
| DRY（重复逻辑消除） | ⚠️ 白名单校验两处重复 | **R2** |

## 3. 重复逻辑与隐患清单（重构重点）

| # | 位置 | 问题 | 处理 |
|---|---|---|---|
| D1 | `api/deps.ensure_writable` vs `agent/safety.check_writable` | **同一白名单校验两套实现**，未来规则漂移风险 | R2：合并到 `core/security.py`（或 vault 静态方法），两处调用 |
| D2 | 后端 `markdown.py` vs 前端 `md.js` | frontmatter/wikilink 语法解析**跨语言重复**（两套实现） | R5：**一致性对照表文档化**（语法规则、边界行为），不强行统一代码（成本高），但锁死行为差异 |
| D3 | `SearchService`（core/search.py） | 只是 IndexService 的薄包装（2 个方法转发） | R3：合并进 IndexService 或标注为展示层适配——建议合并，减少一层间接 |
| D4 | routes_agent `_deps_for` | 为 confirm 构造 AgentDeps，有点别扭 | R2：PendingStore.apply 改接收显式参数（vault/index/backup/settings）而非整个 deps |
| D5 | `app/core/__init__.py` | `from app.core import backup, vault` 导入副作用 | R3：移除，改显式导入 |

## 4. 重构计划（R0-R6）

> 原则：**行为不变（98 测试守护）、小步提交、每步有验收**。逻辑层不重构结构，只清理卫生。

### R0 工具链落地（无行为变化）✅ 2026-07-31 完成
- [x] ruff 配置：`[tool.ruff.lint.flake8-bugbear] extend-immutable-calls`（精确豁免 FastAPI Depends/Query/Header 标准模式）→ `--fix` 自动修 + 手动修 E501/B007/E402/B017
- [x] mypy：routes 层 `dict` → `dict[str, Any]`（脚本 `scripts/fix_mypy_annotations.py` 批量 + 手动）、补 sse_gen/lifespan/_deps_for 等注解

## 5. 明确不做的事（避免过度设计）

- ❌ 不引入 repository 层抽象（本项目无数据库 ORM，SQLite 已封装在 core）
- ❌ 不拆分 core 为 services/repositories 两层（模块已足够内聚，拆分徒增间接）
- ❌ 不合并前后端 markdown 解析为单一实现（跨语言成本高，用文档锁行为）
- ❌ 不动 M0-M5 已验证的分层与依赖方向（那是最大资产）
