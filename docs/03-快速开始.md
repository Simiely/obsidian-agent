# 03 - 快速开始

> 从零把 Obsidian Agent 跑起来。分两种方式：**A. Docker（推荐）** 和 **B. 本地开发**。

---

## 方式 A：Docker 部署（推荐）

### 前置要求

- Docker 20.10+ 与 docker compose v2
- 一个 Obsidian 库（vault）路径，例如 `D:/MyVault`（注意：目录结构必须包含 `.obsidian/` 或任意 md 文件）

### 步骤

```bash
# 1. 进入项目目录，复制配置模板
cd obsidian-agent
cp .env.example .env

# 2. 编辑 .env（至少改这三个）
#    VAULT_PATH=D:/MyVault        ← 你的 Obsidian 库绝对路径
#    LLM_PROVIDER=deepseek        ← deepseek / openai / kimiapi / ollama
#    LLM_API_KEY=sk-xxxx          ← 对应平台的 key（ollama 可不填）

# 3. 启动
docker compose up -d --build

# 4. 查看初始化日志（首次会全量建索引）
docker compose logs -f app

# 5. 打开页面
#    http://localhost:8080
```

### 首次使用

1. 打开页面后先看右上角**索引状态**：显示"构建中 x%"则等待完成；显示"已就绪"即可搜索。
2. 左侧目录树 = 你的 vault 文件；点击任意 md 即可阅读。
3. 对话面板输入任意自然语言指令测试 Agent（需已配置 LLM key）。

### 停止 / 卸载

```bash
docker compose down          # 停止
docker compose down -v       # 停止并删除索引数据（谨慎，备份保留在 data/backups）
```

## 方式 B：本地开发（改代码用）

需要 Python 3.11+ 和 Node 18+。

```bash
# 后端
cd obsidian-agent/app
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -e "../[dev]"
cp ../.env.example ../.env       # 编辑 VAULT_PATH / LLM 配置
uvicorn main:app --reload --port 8080

# 前端（另开终端）
cd obsidian-agent/frontend
npm install
npm run dev                      # Vite dev server，默认 http://localhost:5173 代理到 8080
```

> 前端开发时用 Vite 代理，改前端代码热更新；后端 `--reload` 改代码自动重启。

## 常见问题（FAQ）

| 问题 | 解决 |
|---|---|
| 容器启动后页面 404 | 前端未构建进镜像。`docker compose up -d --build` 强制重建 |
| vault 目录显示为空 | 检查 `.env` 的 `VAULT_PATH` 是否宿主机绝对路径；Windows 用 `D:/MyVault` 格式 |
| 写入文件提示权限拒绝 | 容器内非 root 运行，见 [04-配置参考.md](04-配置参考.md#权限) 的 PUID/PGID 说明 |
| 搜索搜不到中文 | 索引还在构建中，或文件被忽略规则过滤（如 `.obsidian/`）。查看索引状态页 |
| 端口 8080 被占用 | 改 `.env` 的 `PORT`，如 `PORT=9090` |
| Agent 不回复 | 检查 `LLM_PROVIDER` / `LLM_API_KEY` / `LLM_BASE_URL`；Ollama 需确认 `OLLAMA_HOST` 可达 |

> 遇到新问题：先查 [08-踩坑记录.md](08-踩坑记录.md)（很可能有人踩过），没有则按格式补充。
