## 1. 索引与中文检索

### [2026-07-31] jieba 把连字符拆成独立标点 token，混入 FTS5 MATCH 会变 NOT 运算符
- **现象**：`jieba.lcut("docker-compose")` → `['docker', '-', 'compose']`；`-` 若原样拼进 MATCH 查询会被 FTS5 解析成 NOT（`docker -compose` = docker 且不含 compose）。
- **解决**：`tokenize()`/`tokenize_query()` 统一过滤纯标点 token（`_meaningful()`：无字母/数字/中文即丢弃）；含特殊字符的有意义词加引号包裹防注入。
- **影响**：任何拼接 FTS5 查询的路径都必须走 `tokenize_query()`，禁止裸拼用户输入。

### [2026-07-31] tags 预分词后无法还原展示
- **现象**：tags 列预分词（`docker obsidian`）后，`_split_tags` 去掉空格再按逗号切 → `['dockerobsidian']`。
- **解决**：tags 列**不预分词**，存原文逗号连接（`docker,obsidian`）——unicode61 分词器自然切分可检索，且展示可还原。中文 tag（连续中文串）同样可精确命中。
- **影响**：字段的"存/取"两个方向都要设计，检索友好 ≠ 展示友好。

### [2026-07-31] jieba 首次加载慢（~0.7s，走缓存）
- **现象**：`Building prefix dict... Loading model cost 0.657 seconds` 出现在每次冷启动。
- **解决**：首次构建缓存到 `%TEMP%/jieba.cache`（本机已缓存，后续 <0.1s）；容器内注意 temp 目录可写。

## 2. Obsidian 语法与文件兼容

### [2026-07-31] wikilink 正则误匹配 `![[嵌入]]`
- **现象**：`![[图片.png]]` 被 wikilink 正则捕获为普通链接 target="图片.png"。
- **解决**：正则加负向断言 `(?<!\!)\[\[`，排除嵌入语法（embed 与 link 是两种语义）。
- **影响**：解析 Obsidian 方言时务必区分 link/embed/block reference 三种形态。

### [2026-07-31] frontmatter 内联列表 `tags: [a, b]` 需单独处理
- **现象**：`_parse_yaml` 只处理块级列表（`- item`），内联 `[a, b]` 被当标量字符串。
- **解决**：`[` 开头 `]` 结尾的值按逗号切分转列表；块级与内联两种形态都覆盖。
- **影响**：Obsidian 用户两种写法都可能出现，解析器必须兼容。

## 3. Docker 与部署

### [2026-07-31] 沙箱无 docker，compose/镜像无法本地验证
- **现象**：M0 完成后 `docker --version` 报 command not found，`docker compose config` 无法执行。
- **原因**：开发沙箱未安装 docker daemon。
- **解决**：Dockerfile/compose 走静态审阅 + 本地 uvicorn 冒烟（`pytest` + TestClient 覆盖健康检查/静态页/配置校验）；构建与 up 验证留待用户环境执行。M6 发布前在用户侧补一轮 `docker compose up --build` 冒烟。
- **影响**：docker 相关 bug 会晚于本地发现；README 快速上手已标注此前提。

## 4. AI Agent 与 LLM

### [2026-07-31] pydantic-ai 2.x API 与 1.x 差异巨大（先探查再写）
- **现象**：`run_with_tool_approval`（1.x）在 2.21.0 中不存在；`OpenAIChatCompatibleProvider` 是 Literal（预置 provider 名）而非类；`OpenAIModel` 位置变化。
- **解决**：用 `Agent(model="<provider>:<model>")` + 内置 provider（deepseek/ollama/moonshotai 均内置）+ api_key 环境变量注入；实测确认后再写代码。
- **影响**：依赖大版本升级必须用"探查 API → 最小可运行验证 → 集成"三步，不能照文档写。

### [2026-07-31] agent.tool 默认工具名是函数名（带下划线前缀）
- **现象**：`@agent.tool def _tool_write_file` 注册后工具名是 `_tool_write_file`，测试/LLM 按 `write_file` 调用报 KeyError。
- **解决**：`agent.tool(fn, name="write_file")` 显式命名。
- **影响**：工具名是 LLM 与测试的契约，必须稳定可读。

### [2026-07-31] TestModel 生成 dummy 工具参数，无法控制
- **现象**：`TestModel(call_tools=["write_file"])` 生成的参数是 `path="a"`（schema 首值），导致"仅允许 .md"错误。
- **解决**：改用 `FunctionModel`（handler 精确返回 `ToolCallPart(args={...})`），第一轮工具调用、后续轮返回文本。
- **影响**：验证"LLM 调工具"链路用 FunctionModel；TestModel 只适合验证不依赖参数的工具调用。

### [2026-07-31] HITL 实现取舍：暂存式写操作（自研）而非框架 approval
- **决策**：pydantic-ai 2.x 的 HITL（DeferredToolRequests）API 尚不熟悉、调试成本高；改用**自研 PendingStore 暂存式**：write_file 工具只做校验/备份/diff 并暂存，用户确认后才落盘。语义以 system prompt 明确告知 LLM。
- **影响**：写操作安全性与框架解耦，测试性好（test_pending_apply_writes_and_indexes 锁死行为）；LLM 不知晓最终确认结果（可接受，写操作由系统执行）。

## 5. 前端

### [2026-07-31] npm 官方 registry 不可达，但国内镜像可用
- **现象**：`registry.npmjs.org` 返回 000（不可达）；`registry.npmmirror.com` 返回 200 可用；jsdelivr/raw.githubusercontent 也可达。
- **解决**：npm install 加 `--registry=https://registry.npmmirror.com`（Dockerfile 已内置该参数，海外构建可去掉）。
- **影响**：M4 前端因此成功升级 Vue3 + Vite 工程（vue 3.5.40 / vite 6.4.3 / markdown-it 14.3.0）。网络策略：npmjs 官方源被墙，镜像源与部分 CDN 通。

### [2026-07-31] Git Bash heredoc/命令行中的 `\n` 会被转成字面 `/n`
- **现象**：`python - <<'EOF'` 或 `python -c "text='---\ntags:...'"` 里 `\n` 变成字面 `/n` → frontmatter 解析成单行、tags 解析出 `/n-docker`、搜索结果异常——**全是测试脚本数据污染，产品代码无 bug**。
- **解决**：含 `\n` 转义的测试/冒烟脚本一律用 **Write 写文件后执行**（如 `scripts/m4_smoke.py`），不用 heredoc 内联。
- **影响**：Git Bash 管道/参数传递对反斜杠的处理不可靠；凡脚本内嵌多行字符串都要走文件。

### [2026-07-31] fastapi.testclient 报 httpx 弃用警告
- **现象**：`StarletteDeprecationWarning: Using httpx with starlette.testclient is deprecated; install httpx2 instead`。
- **原因**：starlette 新版建议 httpx2，而项目安装的是 httpx 0.28。
- **解决**：M0 阶段忽略（仅警告）；M2/M3 若 TestClient 受影响再评估切换 httpx2（记录待验证项）。

## 6. 其他

### [2026-07-31] 并发关闭 sqlite 连接 → Windows fatal exception: access violation
- **现象**：pytest 全量跑崩溃（`Windows fatal exception: access violation`，栈显示 lifespan `backend.close()` 与初始索引线程 `_set_meta` 同时访问同一连接）。
- **原因**：`check_same_thread=False` 的连接被主线程 close 时，后台线程仍在执行 → sqlite3 C 层并发 UB。
- **解决**：lifespan 退出时**先 join 索引线程（30s 超时）再条件 close**；超时则跳过 close（进程退出由 OS 回收）。
- **影响**：任何"后台线程用共享连接"的模式都要保证关闭前 join；这也是应用正常关停的必备逻辑（防崩溃 + 防数据损坏）。

### [2026-07-31] FTS5 空表 `count(*)` 返回 NULL（而非 0）
- **现象**：build 清空表瞬间 `status()` 撞上窗口 → `int(row["n"])` TypeError: NoneType not subscriptable。
- **原因**：FTS5 空索引的 count 优化返回 NULL（SQLite 常规表返回 0）。
- **解决**：`int(row["n"] or 0)`；涉及 FTS5 计数的地方一律容错。
- **影响**：查询 FTS5 虚拟表计数不能假设恒为 int。

### [2026-07-31] 写操作校验顺序：禁写白名单 vs 路径越界语义
- **现象**：`PUT ../逃逸.md` 返回 403 而非约定的 422（ensure_writable 先拦截了 `..`）。
- **原因**：`Path('../逃逸.md').parts` 含 `'..'`（点开头）→ 被"隐藏目录"规则误判 403。
- **解决**：`ensure_writable` 遇 `..` 直接放行，越界语义统一由 vault 校验报 422；403 专指"合法路径但禁写目录"。
- **影响**：错误码是 API 契约（docs/05），语义不能混。

### [2026-07-31] FastAPI 应用工厂 + 模块级占位（配置错误不阻塞 import）
- **现象**：模块级 `app = create_app()` 在 vault 不存在时抛 VaultError → 测试/工具 import app.main 直接失败。
- **解决**：`create_app(settings)` 工厂可注入配置；模块级创建 try/except 降级为 `_placeholder_app`（health 500 暴露错误）。
- **影响**：测试注入临时配置是 e2e 测试可写的前提；生产配置错误也应有可见入口而非崩溃堆栈。

### [2026-07-31] Windows 上 Path.write_text 会做 \n → \r\n 转换
- **现象**：测试 fixture 用 `write_text("# A\n"*50)` 造文件，读回变成 CRLF，断言连环失败。
- **原因**：Windows 文本模式默认 newline 转换；而 `write_bytes` 不做转换。
- **解决**：测试 fixture 统一用 `write_bytes(x.encode("utf-8"))` 保证确定性。
- **影响**：所有涉及换行的 fixture/测试均须注意；也提醒产品代码写文件时显式控制换行（vault.write 已处理）。

### [2026-07-31] Python bytes 字面量不能含非 ASCII 字符
- **现象**：`b"# 标题\r\n"` 直接 SyntaxError: bytes can only contain ASCII literal characters。
- **解决**：`"# 标题\r\n".encode("utf-8")` 或 `b"\xef\xbb\xbf" + "中文".encode()`。

### [2026-07-31] watchdog 事件 handler 闭包引用外部对象
- **现象**：`on_any_event` 里访问 `self.vault` 报 `'_Handler' object has no attribute 'vault'`，且异常只在后台线程抛（pytest 报 PytestUnhandledThreadExceptionWarning）。
- **解决**：handler 构造时注入 watcher 引用，经 `self._watcher.vault` 访问。
- **影响**：后台线程异常不冒泡，务必靠日志/测试捕获。

### [2026-07-31] cron weekday 语义：cron 0=周日 vs Python weekday() 0=周一
- **现象**：`1-5` 解析后与 Python `dt.weekday()` 直接比较，周一被跳过。
- **解决**：匹配时 `(dt.weekday() + 1) % 7` 转换；文档注明 cron 惯例。
- **影响**：任何实现 cron 的模块都要注意语义转换。

### [2026-07-31] cron next_run 扫描窗口需覆盖跨周末
- **现象**：周五 22:30 触发周一到周五 9:00 的 cron，25 小时窗口内找不到。
- **解决**：窗口扩到 7 天（逐分钟扫描 10080 次，开销可忽略）。

### [2026-07-31] PyPI 直连 SSL 不稳定（SSLEOFError）
- **现象**：`pip install` 偶发 `SSL: UNEXPECTED_EOF_WHILE_READING`，部分包直接失败。
- **解决**：切换清华镜像 `-i https://pypi.tuna.tsinghua.edu.cn/simple`（本机网络环境可用）。
- **影响**：后续所有 pip 安装默认加镜像参数。

## 7. 备份与数据安全（M1 开发期）

### [2026-07-31] 快照 id 秒级精度冲突 → 增量失效（严重）
- **现象**：同一秒创建两次快照 id 相同（`snap-20260731-225755`），增量判断 `prev < snap` 恒 False → 每次全量复制；更严重时 `restore_all` 用旧 id 取到被覆盖的新快照目录。
- **原因**：id 只含秒级时间戳；createdAt 也是秒级精度。
- **解决**：① id 加 `uuid4().hex[:4]` 后缀保证唯一 ② createdAt 用微秒精度 ③ **"最新快照"一律按 manifest.createdAt 排序比较，绝不按 id 字典序**。
- **影响**：时间序比较必须基于 createdAt；id 只当唯一标识。测试 `test_incremental_hardlink` 锁死该行为。

### [2026-07-31] 快照 id 随机后缀导致字典序 ≠ 时间序
- **现象**：`-9c93` vs `-4515` 字典序与创建先后相反，`sorted(glob, reverse=True)` 得到错误顺序。
- **解决**：排序统一改 `list_snapshots()` 内按 `createdAt` 降序；禁止外部依赖 id 序。

### [2026-07-31] 快照 verify 需要校验基准（manifest checksums）
- **现象**：初始实现让校验文件"自己比自己"，永远通过，篡改检测失效。
- **解决**：创建快照时把抽样文件（≤100 个）MD5 写入 manifest，verify 时对照 manifest 比对。

## 0. 调研已确认的坑（2026-07-31，开工前预埋）

> 来源：docs/09-技术调研与方案审核.md。以下坑是外部实战验证过的，**实现时直接按对策做**，不必再踩。

- **[调研] Meilisearch 不适合本项目**
  - 现象：中文分词器（jieba-rs）不可自定义/替换；高亮 API 有 bug（边缘 case 返回错误 offset）；索引更新非实时（几秒延迟）；有实测（7,647 篇中文文档）Hit@1 仅 39.4%，延迟 18.5s。
  - 对策：默认用 SQLite FTS5 + jieba 预分词（实测 Hit@1 63.6%、延迟 2.1s），Meilisearch 仅作逃生通道。
- **[调研] FTS5 默认 unicode61 分词器对中文整串切分**
  - 现象：存"北京市朝阳区"，搜"朝阳"不命中（unicode61 把连续中文当一个 token）。
  - 对策：入库前用 jieba 预分词（token 间加空格），query 同管线分词；支持自定义词典。
- **[调研] Meilisearch/Typesense 中文专业术语命中差**
  - 现象：企业文档实测，Typesense 单字切分几乎不可用，Meili 专业术语出错。
  - 对策：jieba 自定义词典（`data/userdict.txt`）维护领域词，命中率可控。
- **[调研] 自研 Obsidian 语法渲染成本高且持续失配**
  - 现象：wikilink/callout/高亮/嵌入/注释等方言语法多，自研插件长期跟不上。
  - 对策：直接用 `@quartz-community/obsidian-flavored-markdown`（Quartz 官方维护），零自研。
- **[调研] 前端 FlexSearch 不适合做主检索**
  - 现象：FlexSearch 查询快（万级 2-8ms）但中文需自维护分词（二元分词质量差）、无 BM25 语义排序、复杂查询弱。
  - 对策：主检索走后端 FTS5；前端 FlexSearch 仅作输入联想增强（非必须）。
- **[调研] 现成"Obsidian + AI"项目均缺一块能力（2026-07 状态）**
  - 现象：Khoj 缺网页编辑 vault 原文件（编辑靠 Obsidian 客户端插件）；obsidian-ai-workspace 缺全文检索且仅支持 Claude；Ignis 缺检索与 Agent；MCP 系（obsidian-agentic-rag / obsidian-mcp）无 Web UI。
  - 对策：自建一体化方案成立；详情与备选路线见 docs/09 §5。
- **[调研] Khoj 若被引入需注意 AGPL-3.0**
  - 现象：Khoj 是 AGPL 协议，若基于它做对外服务需开源修改。
  - 对策：本项目自研（MIT）不引入；仅作功能对标参考。

## 预判风险清单（规划阶段，M0-M6 开发时逐条验证回填）

### 1. Obsidian 特殊语法被编辑器破坏
- **风险**：md 含 frontmatter、`[[]]`、callout（`> [!note]`）、`==高亮==`、内嵌 LaTeX。若编辑/保存时做任何"规范化"重写，会毁掉整个库。
- **对策**：编辑视图 = 纯文本原样保存（不 WYSIWYG）；渲染只发生在阅读视图；保存逻辑对内容零改写。测试用例锁死「读入 → 写出 → 字节一致」。

### 2. 中文全文检索命中率差
- **风险**：SQLite FTS5 默认 unicode61 tokenizer 对中文按字切分，搜"分词"可能搜不到"分词方案"中的连续词，且无词义。
- **对策**：jieba 分词后入库（内容存一份分词串 + 保留原文做高亮）；检索时同样分词；`fts5` 用 `tokenize='unicode61'` + 自定义预分词。用例：搜「docker」命中 "Docker 部署"，搜「分词」命中 "中文分词方案"。

### 3. 容器写权限（PUID/PGID）
- **风险**：容器内非 root 用户与宿主机 uid 不一致 → vault 写入"权限拒绝"。
- **对策**：支持 `PUID/PGID` 环境变量切换运行用户；Linux 部署文档明确说明 `id -u` 步骤。测试：以非 root 用户写入挂载目录。

### 4. watchdog 事件风暴
- **风险**：大库首次启动时文件系统事件堆积，或 Obsidian 批量保存触发大量事件 → 索引疯狂重建。
- **对策**：debounce（默认 2s）+ 每文件去重（按 mtime+size 判断是否真变更）+ 增量队列上限。

### 5. Agent 误操作破坏笔记
- **风险**：LLM 生成的写入内容可能有误（删错段落、截断文件、编码混乱）。
- **对策**：写前强制备份到 `data/backups/`；写操作必须用户确认（SSE `tool` 事件 + `/api/agent/confirm`）；`MAX_FILE_BYTES` 以上禁止重写；禁写 `.obsidian/` 等目录。测试：模拟工具调用全链路。

### 6. 编码与换行符（Windows 历史文件）
- **风险**：部分 md 可能是 GBK / UTF-8 带 BOM；LF/CRLF 混用。读错乱码，写错破坏全文。
- **对策**：读取用 `utf-8-sig`（自动去 BOM）→ 解码失败回退 GBK；**写入恒为 UTF-8 无 BOM**，换行保留原文件风格（检测首个换行符）。测试：造 GBK/带 BOM/CRLF 三种 fixture。

### 7. 路径穿越（安全）
- **风险**：API 参数 `path=../../etc/passwd` 越界读、写任意文件。
- **对策**：后端统一 `core/vault.py` 的 `resolve_safe_path()`，`pathlib.resolve()` 后必须仍位于 vault 根内；拒绝绝对路径/盘符/`..`；API 层一律走该校验函数。测试：路径穿越用例必须覆盖。

### 8. markdown 渲染库对 Obsidian 语法支持不全
- **风险**：渲染库默认不支持 callout / wikilink / 高亮 / 嵌入。
- **对策**：直接用 `@quartz-community/obsidian-flavored-markdown`（Quartz 官方插件包，remark 生态）+ Mermaid 懒加载。阅读视图 CSS 尽量贴近 Obsidian 观感（深色/浅色跟随）。

### 9. LLM API key 泄漏
- **风险**：key 写进代码 / 镜像 / 前端 bundle。
- **对策**：key 只进 `.env`（compose `env_file`）；前端不接触 key（Agent 调用全在后端）；日志脱敏（`LOG_LEVEL=debug` 时 key 打码）。检查项：`docker history` 无 key、`grep -r key frontend/dist` 为空。

### 10. 大库全量索引慢 / 中断
- **风险**：数万文件首次索引分钟级，中途崩溃则白干。
- **对策**：分批（`INDEX_BATCH_SIZE`）+ 事务提交 + 断点续传（记录已索引文件 mtime 快照，重启后跳过未变更文件）；进度经 `/api/index/status` 上报。

### 11. 备份目录放错位置（自我递归/污染）
- **风险**：备份目录若建在 vault 内部，会被索引、被下一个快照再次备份、甚至被"整库恢复"覆盖自身 → 备份链断裂。
- **对策**：强制 `BACKUP_DIR` 位于 vault 之外（默认 `{DATA_DIR}/backups`）；启动时校验若在 vault 内直接报错退出；`IGNORE_DIRS` 永远包含备份目录。测试：误配置在 vault 内 → 启动失败提示。

### 12. 快照一致性（文件写入中）
- **风险**：快照扫描时 Obsidian/用户正在写文件 → 快照里出现半截文件。
- **对策**：快照对单个文件先复制到临时再置位（或对 >1MB 文件做双读校验）；失败重试 3 次仍不一致则跳过并记 warning。测试：快照过程中并发修改文件。

### 13. 硬链接增量在跨卷/部分文件系统失效
- **风险**：NTFS/APFS/ext4 支持硬链接，但 FAT32/exFAT、跨 volume 挂载时硬链接会失败或静默复制。
- **对策**：`os.link` 失败自动降级为复制；快照 manifest 记录"链接/复制"方式，校验时按 manifest 处理。测试：临时目录用不支持硬链接的挂载点（或 mock link 抛错）验证降级。

### 14. 整库恢复误操作
- **风险**：恢复方向反了 / 选错快照 / 恢复中中断 → vault 数据比恢复前更糟。
- **对策**：恢复前**强制先建"恢复前快照"**；双确认（UI 输入 `RESTORE` 确认码）；恢复期间服务进入只读模式；支持恢复任务中断后的继续/回滚。测试：恢复流程全链路 + 中断恢复。
