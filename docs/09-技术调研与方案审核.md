# 09 - 技术调研与方案审核

> 本文件是项目的**选型决策记录**：为什么用 FTS5+jieba、为什么用 Pydantic AI、为什么自建而不是用现成项目。
> 改架构前先看这里。所有结论均有外部资料/实测数据支撑，来源见文末。

## 1. 审核范围与方法

- **触发**：开工前对关键选型做完整技术审核，避免返工。
- **轮次**：两轮共 8 路网络调研（2026-07-31），交叉验证现成方案、检索引擎、渲染方案、Agent 框架。
- **结论速览**：① 现成开源项目**无一同时满足**用户全部需求 → 自建成立；② 检索用 SQLite FTS5 + jieba 有实测数据支撑；③ 渲染用 Quartz 官方插件；④ Agent 用 Pydantic AI。

## 2. 关键决策一：全文检索 = SQLite FTS5 + jieba 预分词（默认）

### 2.1 实测数据（第三方，2026）

| 维度 | Meilisearch + 6 层 pipeline | SQLite + jieba 预分词 FTS5 |
|---|---|---|
| Hit@1（首条命中率，7,647 篇中文语料） | 39.4% | **63.6%（+24.2pp）** |
| Hit@5 | 72.7% | 81.8% |
| 平均延迟 | 18,480 ms | **2,109 ms（快 8.8×）** |
| 中文分词控制权 | Meili 内置 Rust jieba，**不可替换** | 完全自主（可自定义词典） |
| 部署/维护 | 多服务 + Docker compose | **单个 .db 文件**，scp 即部署 |

> 来源：jacobmei.com《繁體中文全文搜尋引擎實戰筆記(四)》2026-04（从 Meilisearch 翻到 SQLite，结论为"跑得快、可解释、可改"）。

### 2.2 为什么不是 Meilisearch / Typesense / Elasticsearch

- **Meilisearch**：中文分词器不可自定义（官方 jieba 包即唯一选择）；高亮 API 有 bug（边缘 case 返回错误 offset）；索引更新非实时（数据量大后几秒延迟）；企业云盘实测专业术语分词出错。
- **Typesense**：中文按单字切分，实测几乎不可用（"人防工程"切成"人/防"）。
- **Elasticsearch + IK**：中文最强，但需要 JVM + 集群运维，对个人知识库是杀鸡用牛刀。
- 结论：**个人/家庭级知识库场景，FTS5 是被低估的正确选择**。独立实测：100 万条 × 500 字记录，FTS5 单词查询 ~5ms、短语 ~20ms、BM25 内置排序、highlight/snippet 高亮内置、索引约为原文 30-50%。官方明确"笔记应用、文档搜索（Obsidian/Notion 类产品的本地搜索）"正是适合场景。

### 2.3 中文分词的实现要点

- FTS5 默认 unicode61 把连续中文当一个 token（搜"朝阳"命中不了"北京市朝阳区"）→ **入库前 jieba 分词，token 以空格连接；查询走同一分词管线**。
- 支持 jieba 自定义词典（`data/userdict.txt`），可维护个人/领域术语 → 命中率可控（优于 Meili 固定分词）。
- 保留原文列用于高亮/摘要（FTS5 外部内容表 + 触发器，避免重复存储）。

### 2.4 前端全文索引（FlexSearch/MiniSearch）为何不选

- FlexSearch 实测（10k-50k 条）查询 2-8ms，很快；但**中文需自维护分词**（二元分词质量差）、无 BM25 语义排序、复杂查询弱。
- 定位：适合"输入即搜"的即时过滤，不适合作为主检索。
- 取舍：**主检索仍走后端 FTS5**（保证中文质量与多端一致）；前端可选用 FlexSearch 做输入联想（增强项，非必须）。

## 3. 关键决策二：渲染 = remark/rehype + Quartz 官方插件（零自研）

- **`@quartz-community/obsidian-flavored-markdown`**（Quartz 默认插件，独立 npm 包，MIT，2026-07 仍在维护）：
  - 完整支持 wikilinks（`[[Page]]` / `[[Page|别名]]` / `[[Page#Heading]]` / `[[Page#^block-id]]`）、embeds（`![[img.png|300]]`）、callouts（13 种类型 + 折叠 `+/-` + 嵌套）、`==高亮==`、`%%注释%%`、tags、Mermaid、YouTube/视频嵌入。
  - 不覆盖的方言（如 DataView 查询块）作为已知限制记录，前端按需扩展。
- 备选 markdown-it + 手写插件：需要自己实现上面全部语法，持续失配 → 放弃。
- **编辑视图与渲染分离**：编辑 = 纯文本（保留原始字节，不 WYSIWYG）；渲染只发生在阅读视图。

## 4. 关键决策三：Agent 框架 = Pydantic AI v1.x

### 4.1 2026 主流框架对比

| 维度 | LangGraph | OpenAI Agents SDK | Claude Agent SDK | **Pydantic AI** |
|---|---|---|---|---|
| 模型灵活性 | 任意 ChatModel | OpenAI 优先 | **仅 Claude** | 任意（模型串切换） |
| HITL 工具批准 | 一等公民 | 手动 | hooks | **内置** |
| MCP | 适配器 | 适配器 | 原生 | **原生（客户端+服务端）** |
| 类型安全 | 弱 | 中 | 中 | **强（Pydantic 校验）** |
| 同类功能代码量 | ~280 行 | ~200 行 | ~190 行 | **~160 行** |
| 版本状态 | 稳定 | 稳定 | 稳定 | **v1.0（2025-09 起 API 稳定承诺）** |
| 定位 | 复杂状态机/多 Agent | 线性客服路由 | 编码/文件自动化 | 类型安全、provider 中立 |

### 4.2 为什么不是其他

- **LangGraph**：我们是单 Agent + 4-5 个工具 + HITL，图编排/持久化是过度设计。
- **Claude Agent SDK**：锁死 Claude；用户需要 DeepSeek/Ollama（国内环境）→ 直接排除。
- **OpenAI Agents SDK**：OpenAI 优先；DeepSeek 经 base_url 兼容可用但 guardrails 等依赖 OpenAI 特性，约束多。
- **自研循环**：可行但重复造轮子——流式、校验重试、工具参数校验、错误处理都要自己写。
- **Pydantic AI 契合点**：与 FastAPI 同作者生态（pydantic 类型栈一致）；工具 = 类型化 Python 函数（docstring 自动生成 schema）；内置 HITL 工具批准（写前用户确认的直接实现）；`pydantic-graph` 留作未来复杂流程扩展。

### 4.3 保持自研的部分（业务层，不外包）

- `agent/safety.py`：备份、diff、路径白名单、禁写目录——与框架无关的安全层。
- `agent/tools/*`：read_file / write_file / search / list_tree——实现细节自控。
- 会话持久化与 SSE 推送：由我们的 API 层负责。

## 5. 关键决策四：自建 vs 现成项目（第二轮调研核心）

### 5.1 候选项目逐个审核（2026-07-31 状态）

| 项目 | 网页浏览 | 网页编辑原文件 | 全文检索 | AI Agent | LLM 灵活性 | Docker | 许可证 | 结论 |
|---|---|---|---|---|---|---|---|---|
| **Khoj**（khoj-ai/khoj） | ✅ Web UI（搜索/聊天/上传） | ❌ 编辑靠 Obsidian 客户端插件 | ✅ 语义+全文（pgvector） | ✅ 强（自定义 Agent/自动化/研究模式） | ✅ 任意（Ollama/OpenAI/Claude/Gemini） | ✅ | AGPL-3.0 | **缺网页编辑**，与需求部分重叠 |
| **obsidian-ai-workspace**（Sunshow） | ⚠️ noVNC 远程桌面（非原生 Web） | ✅（noVNC 内原版） | ❌（开发计划 TODO） | ⚠️ 技能执行器体系 | ❌ **仅 Claude** | ✅ | MIT | 缺检索、锁 Claude、无认证 → 不满足 |
| **Ignis**（Nystik-gh/ignis） | ✅ 真·网页版原版 Obsidian | ✅ 原版体验 | ❌（无索引，依赖插件） | ❌ | - | ✅ | 开源 | 浏览/编辑最强，**缺检索与 Agent** |
| **obsidian-agentic-rag**（MCP） | ❌（仅 MCP 工具） | ❌ | ✅ 混合检索+增量 | ✅（经 Claude Code） | 本地 Ollama | ✅ | - | 无 Web UI |
| **obsidian-mcp**（maxkuminov） | ❌（仅 MCP 工具） | ❌ | ✅（pgvector 全文） | ✅（经 MCP 客户端） | 插拔 | ✅ | MIT | 无 Web UI |
| **本项目（自建）** | ✅ | ✅ 轻量视图（+可选 Ignis F21） | ✅ FTS5+jieba | ✅ Pydantic AI | ✅ DeepSeek/OpenAI/Kimi/Ollama | ✅ | MIT | **全需求覆盖** |

### 5.2 结论

> **没有任何现成项目同时满足：网页浏览/编辑 vault 原文件 + 逐字全文检索（中文）+ AI Agent 编辑 + 多 LLM。** 最接近的两个（Khoj、obsidian-ai-workspace）分别缺"网页编辑"和"检索/多模型"。因此自建一体化方案是当前需求下的最优解，而非重复造轮子。

### 5.3 如果愿意砍需求（备选路线，供用户决策）

| 可砍的需求 | 替代方案 | 代价 |
|---|---|---|
| 网页编辑（接受在 Obsidian 客户端里编辑） | 直接用 **Khoj**（Docker 部署，配 Ollama/DeepSeek） | 失去网页工作台；AGPL 注意；编辑回写体验不如一体 |
| 自研编辑视图（接受原版体验） | **Ignis + 本项目索引/Agent 服务**混合 | 两套部署；搜索跳转定位联动受限；Ignis 首启需网络拉 Obsidian |

## 6. 借鉴清单（从调研项目吸收，写进 M1/M2/M5）

1. **增量索引用 MD5 比对**（obsidian-agentic-rag）：跳过未变更文件，而非仅靠 mtime。
2. **watchdog 自动重索引**（obsidian-agentic-rag / Khoj）：文件变更事件 → debounce → 只处理变更。
3. **技能/自动化体系**（obsidian-ai-workspace）：v0.2+ 考虑"技能"概念（把常用 Agent 工作流固化）。
4. **MCP 对齐与暴露**（obsidian-mcp / Pydantic AI 原生支持）：工具 schema 对齐 MCP 规范，v0.2+ 可暴露 MCP 端点给 Claude Code 等客户端。
5. **guardrails 先行**（OpenClaw 实战）：Agent 权限按"确认-分级"设计——读白名单、写必确认、系统操作禁止。
6. **PUID/PGID 与 volume 权限**（Ignis / linuxserver 系）：容器非 root 运行，权限文档明确。

## 8. 未验证点（诚实声明）

- Pydantic AI 的 HITL 工具批准与 SSE 流式的具体集成方式，需在 M5 用真实 API 冒烟验证。
- `@quartz-community/obsidian-flavored-markdown` 为 Quartz 生态（remark 管线），与 Vue3 集成需确认插件类型（transformer）与 vite 构建兼容性。
- Ignis 首次启动从 GitHub 拉 Obsidian 源码，国内网络可能慢；仅影响 F21 可选功能。
- FTS5 实测数据来自第三方博客（繁体中文语料），与本项目场景同构（中文笔记检索），但非同一数据集；M2 用本项目测试集复验。

## 10. 备份子系统选型（2026-07-31 追加）

用户新增需求：**防止数据错误无法挽回** → 增加完整备份子系统。

### 10.1 方案对比

| 方案 | 空间效率 | 恢复粒度 | 依赖 | 说明 |
|---|---|---|---|---|
| **快照目录 + 硬链接增量**（选） | 高（未变文件零占用） | 任意（单文件/整库） | 无（标准库） | 快照即普通目录，可人工直接读取/拷贝；`os.link` 失败自动降级复制 |
| Restic / Borg | 极高（内容去重+加密） | 任意 | 外部二进制 | 功能强但引入重依赖；v0.2+ 作为可插拔后端可选 |
| git 裸仓库快照 | 中 | 单文件/整库 | git | 需维护提交；vault 非 git 时额外引入；日志语义与快照不同 |
| 打包 zip/tar 全量 | 低（全量重复） | 整库为主 | 无 | 最简单但空间浪费、恢复不便 |

### 10.2 设计要点（对应 docs/02 §3.4、docs/04 §1.5、docs/05 §3.7-3.9）

1. **三层防线**：写前单文件备份（已有）→ 定时整库快照（默认每日 02:00）→ 恢复前强制再快照。
2. **触发时机**：定时 cron / 手动按钮 / Agent 批量操作与索引重建前自动快照。
3. **保留策略**：`BACKUP_RETENTION=7d,4w,3m`（日/周/月），自动清理防膨胀。
4. **一致性**：单文件临时复制置位 + 失败重试；`BACKUP_VERIFY` 抽样校验（文件数 + checksum）。
5. **恢复安全**：整库恢复需双确认（输入 `RESTORE` 码）+ 恢复期间只读模式 + 支持中断后继续/回滚。
6. **硬链接降级**：跨卷/FAT32 等不支持硬链接时自动复制（坑 #13）。
7. **备份目录强制在 vault 外**（坑 #11），启动校验。
