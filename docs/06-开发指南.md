# 06 - 开发指南

> 面向开发者的协作规范：环境、代码风格、测试、提交与新增模块流程。

---

## 1. 环境准备

```bash
# 后端
cd app
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -e "..[dev]"                             # 含 pytest/ruff/mypy

# 前端
cd frontend
npm install
```

## 2. 代码规范

| 项 | 规范 |
|---|---|
| Python 版本 | 3.11+，类型标注**必须完整**（mypy strict） |
| 格式化 | ruff format（100 列） |
| 排序 | ruff 自动（isort 规则） |
| 前端 | eslint + prettier（默认配置） |
| 命名 | Python：snake_case；前端：组件 PascalCase、变量 camelCase |
| 注释 | 中文注释；公共 API 必须写 docstring（含参数说明） |

```bash
# 提交前本地检查
cd app && ruff check . && ruff format --check . && mypy .
cd frontend && npm run lint && npm run build
```

## 3. 测试

```bash
cd app && pytest tests/ -v
```

| 目录 | 内容 | 关键用例 |
|---|---|---|
| `tests/unit/test_vault.py` | 目录树/读写/忽略规则 | 忽略 `.obsidian`；Windows 路径容错；GBK 文件读取 |
| `tests/unit/test_markdown.py` | frontmatter/正文提取 | `[[]]` 链接保留；callout 识别 |
| `tests/unit/test_indexer.py` | FTS5 索引/检索 | **中文分词命中**；增量更新；删除同步 |
| `tests/unit/test_safety.py` | 路径校验/备份 | `../` 越界拒绝；禁写目录拒绝；备份生成 |
| `tests/e2e/test_api.py` | API 全链路 | 树→读→写→搜→Agent 模拟 |

> 新增功能必须有对应测试；修复 bug 先写复现用例再改代码。

## 4. Git 提交规范

```
feat(vault): 支持目录树按 mtime 排序
fix(indexer): 修复中文分词在 FTS5 中的命中偏移偏移
docs(readme): 补充快速开始 FAQ
test(safety): 增加路径穿越用例
chore(deps): 升级 jieba 至 0.42
```

- 格式：`<type>(<scope>): <subject>`，subject 用中文简述
- 一次提交只做一件事；破坏性变更在 CHANGELOG 标注

## 5. 如何新增一个模块（以"新增 Agent 工具"为例）

1. **加文件**：`app/agent/tools/my_tool.py`，实现 `def my_tool(vault, arg1) -> dict`，返回 JSON 可序列化结果
2. **加 schema**：同文件内定义 `MY_TOOL_SCHEMA = {...}`（OpenAI function calling 格式）
3. **注册**：`app/agent/loop.py` 的 `TOOL_REGISTRY` 里加一项
4. **加测试**：`tests/unit/test_safety.py` 或新建 `test_my_tool.py`
5. **更新文档**：`docs/05-API参考.md`（如涉及 API）、`docs/01-功能说明.md` 功能表、`docs/07-更新日志.md`
6. **更新记忆**：`docs/08-踩坑记录.md`（如有新坑）

> 新增模块的黄金法则：**单一职责、依赖只朝一个方向、有测试、文档同步**。

## 6. 调试技巧

- 后端日志：`docker compose logs -f app`；本地开发直接看终端
- 索引问题：`GET /api/index/status` 查看进度；`POST /api/index/rebuild` 重建
- LLM 问题：临时设 `LOG_LEVEL=debug` 可看到工具调用 JSON（注意日志不要打印 API key）
- 前端联调：Vite 代理 `/api` 到 8080，网络面板直接看请求

## 7. 发布流程（v0.x.y）

1. 全部测试绿 + 前端 build 通过
2. `docker compose up -d --build` 冒烟验证（新 vault 全流程走一遍）
3. 更新 `docs/07-更新日志.md`（Keep a Changelog 格式）
4. 打 tag：`git tag v0.1.0 && git push --tags`
